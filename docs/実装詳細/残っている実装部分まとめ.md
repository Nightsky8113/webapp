## 🚧 未実装の主要機能

### 1. 外部API統合（コストがかかるため後回し）⏸️

これらの機能は、有料の外部APIを使用するため、現在は実装を見送っています。

#### 1.1 Google Maps Directions API
**目的**: 最寄り駅から店舗までの徒歩時間を自動計算

**現状**:
- `stores.summary_walk_minutes`フィールドはデータベースに存在
- 現在は手動でデータを入力している
- 自動計算機能は未実装

**実装に必要なもの**:
- Google Cloud Platformのアカウント
- Google Maps Directions APIのAPIキー
- 有料API（リクエスト数に応じて課金）

**実装内容**:
- 店舗データ登録時に、最寄り駅から店舗までの経路を取得
- 経路情報から徒歩時間を計算
- データベースの`summary_walk_minutes`を自動更新

#### 1.2 Google Cloud Vision API
**目的**: チラシ画像から商品情報を自動抽出（OCR処理）

**現状**:
- `flyers.ocr_done`フラグはデータベースに存在
- OCR処理機能は未実装
- 商品データは手動で入力している

**実装に必要なもの**:
- Google Cloud Platformのアカウント
- Google Cloud Vision APIのAPIキー
- 有料API（画像処理数に応じて課金）

**実装内容**:
- チラシ画像をアップロード
- Vision APIで画像内のテキストを抽出
- 抽出したテキストを商品情報として保存

#### 1.3 OpenAI API
**目的**: OCRで抽出したテキストを構造化（商品名、価格、ジャンルなどに分類）

**現状**:
- OCR処理自体が未実装のため、この処理も未実装

**実装に必要なもの**:
- OpenAIのアカウント
- OpenAI APIのAPIキー
- 有料API（リクエスト数に応じて課金）

**実装内容**:
- Vision APIで抽出したテキストを取得
- OpenAI APIでテキストを解析し、商品情報として構造化
- 商品名、価格、ジャンルなどを自動分類
- データベースの`items`テーブルに自動保存

### 2. バックエンド処理パイプライン（外部API依存）⏸️

#### 2.1 OCR処理パイプライン
**目的**: チラシ画像アップロード後に、自動的にOCR処理を実行

**実装内容**:
1. 画像アップロード完了後、バックエンドに処理リクエストを送信
2. バックエンドがVision APIでOCR処理を実行
3. OpenAI APIでテキストを構造化
4. データベースに商品情報を保存
5. `ocr_done`フラグを`true`に更新

**必要なもの**:
- Vision APIとOpenAI APIの統合（上記1.2、1.3が前提）
- バックエンドサーバーまたはSupabase Edge Functions

#### 2.2 徒歩時間の自動更新
**目的**: 店舗データ登録・更新時に、自動的に徒歩時間を計算

**実装内容**:
1. 店舗データが登録・更新されたとき
2. Directions APIで最寄り駅から店舗までの経路を取得
3. 経路情報から徒歩時間を計算
4. `summary_walk_minutes`を自動更新

**必要なもの**:
- Directions APIの統合（上記1.1が前提）
- データベーストリガーまたはバックエンド処理

## 📝 補足

### 外部API統合について
外部APIを統合する場合、以下のコストがかかります：

- **Google Maps Directions API**: リクエスト数に応じて課金（月額$200相当まで無料）
- **Google Cloud Vision API**: 画像処理数に応じて課金（月額$300相当まで無料）
- **OpenAI API**: リクエスト数とトークン数に応じて課金（従量課金）

詳細は以下のドキュメントを参照してください：
- `docs/API関連/APIコストまとめ.md`
- `docs/API関連/Google_Places_APIコスト分析.md`

### 手動入力での運用
外部APIを使用しない場合でも、以下の方法で運用可能です：

- **徒歩時間**: データ登録時に手動で入力
- **商品情報**: チラシを見ながら手動で入力
- **OCR処理**: 不要（商品情報を直接入力）

この方法でも、アプリケーションは十分に機能します。
