# 位置情報受け渡し方法の比較

## 概要

ウェルカムページから店舗詳細ページに遷移する際に、位置情報を渡す方法を比較します。

---

## 方法1: URLパラメータ（現在の方法）

### 実装例
```javascript
window.location.hash = `/store/${storeId}?lat=${lat}&lng=${lng}`;
```

### メリット
- ✅ URLに情報が含まれるため、リンクをコピーして共有できる
- ✅ ブラウザの戻る/進むボタンで動作する
- ✅ シンプルで理解しやすい
- ✅ ページリロード時も位置情報が保持される

### デメリット
- ❌ URLが長くなる（見た目が悪い）
- ❌ 位置情報がURLに露出する（プライバシー的には問題ないが、見た目）
- ❌ 位置情報がない場合、URLに含める必要がある（取得処理が必要）

---

## 方法2: LocalStorage（既に実装済み）

### 実装例
```javascript
// 位置情報を保存
saveToLocalStorage('userLocation', { lat: 35.6812, lng: 139.7671 });

// 位置情報を取得
const location = getFromLocalStorage('userLocation');
```

### 現在の実装状況
- ✅ `src/utils/location.js`で既に実装されている
- ✅ 位置情報取得時に自動的にLocalStorageに保存される

### メリット
- ✅ URLがクリーンになる
- ✅ ブラウザを閉じても位置情報が保持される
- ✅ 既に実装済み
- ✅ 他のページでも同じ位置情報を使い回せる

### デメリット
- ❌ ブラウザを変えると共有されない
- ❌ プライベートモードでは制限される場合がある
- ❌ リンクをコピーしても位置情報は含まれない

### 実装方法
```javascript
// router.jsで位置情報を取得
import { getFromLocalStorage } from './utils/helpers.js';

export async function renderPage(userLocation) {
    // URLパラメータがない場合、LocalStorageから取得
    if (!userLocation) {
        userLocation = getFromLocalStorage('userLocation');
    }
    // ... 以下同じ
}
```

## 方法3: SessionStorage

### 実装例
```javascript
// 位置情報を保存
sessionStorage.setItem('userLocation', JSON.stringify({ lat: 35.6812, lng: 139.7671 }));

// 位置情報を取得
const location = JSON.parse(sessionStorage.getItem('userLocation'));
```

### メリット
- ✅ URLがクリーンになる
- ✅ タブを閉じると自動的に削除される（プライバシーに良い）
- ✅ セッション内で位置情報が保持される

### デメリット
- ❌ タブを閉じると消える
- ❌ ブラウザを閉じると消える
- ❌ リンクをコピーしても位置情報は含まれない

---

## 方法4: メモリ内の状態管理（グローバル変数）

### 実装例
```javascript
// src/utils/state.js（新規作成）
let userLocation = null;

export function setUserLocation(location) {
    userLocation = location;
}

export function getUserLocation() {
    return userLocation;
}

// 使用例
import { getUserLocation, setUserLocation } from './utils/state.js';

// 位置情報を設定
setUserLocation({ lat: 35.6812, lng: 139.7671 });

// 位置情報を取得
const location = getUserLocation();
```

### メリット
- ✅ 最もシンプル
- ✅ パフォーマンスが良い（ストレージアクセス不要）
- ✅ URLがクリーン

### デメリット
- ❌ ページリロードで消える
- ❌ タブを閉じると消える
- ❌ リンクをコピーしても位置情報は含まれない
- ❌ ブラウザの戻る/進むボタンで状態が失われる可能性がある

## 方法5: ハイブリッド（推奨）

### 実装例
```javascript
// router.js
export async function renderPage(userLocation) {
    // 優先順位:
    // 1. URLパラメータから取得（最も優先）
    // 2. LocalStorageから取得（フォールバック）
    // 3. なければnull（位置情報なしで表示）
    
    const { route, params, queryParams } = getCurrentRoute();
    
    // URLパラメータから取得
    if (queryParams.lat && queryParams.lng) {
        userLocation = {
            lat: parseFloat(queryParams.lat),
            lng: parseFloat(queryParams.lng)
        };
    } else {
        // LocalStorageから取得（フォールバック）
        const cachedLocation = getFromLocalStorage('userLocation');
        if (cachedLocation) {
            userLocation = cachedLocation;
        }
    }
    
    // ... 以下同じ
}
```

### メリット
- ✅ URLパラメータがある場合はそれを使用（共有可能）
- ✅ URLパラメータがない場合はLocalStorageを使用（自動取得）
- ✅ 最も柔軟で使いやすい

### デメリット
- ❌ 実装が少し複雑

---

## 推奨実装方法

### 推奨: 方法5（ハイブリッド）

現在のアプリケーションに最適なのは**ハイブリッド方式**です：

1. **URLパラメータがある場合**: URLパラメータを優先（共有可能）
2. **URLパラメータがない場合**: LocalStorageから取得（自動取得）

これにより：
- 位置情報検索ページから遷移した場合：URLパラメータを使用
- ウェルカムページから遷移した場合：LocalStorageから取得

### 実装の利点

1. **既存のLocalStorage実装を活用**
   - `src/utils/location.js`で既に位置情報をLocalStorageに保存している
   - 追加実装が少ない

2. **ユーザー体験が向上**
   - 位置情報を一度取得すれば、以降は自動的に使用される
   - URLが長くならない

3. **柔軟性**
   - URLパラメータで位置情報を指定することもできる（共有機能）

## 比較表

| 方法 | URLの見た目 | 共有可能 | リロード後保持 | 実装の複雑さ | 推奨度 |
|------|------------|---------|--------------|------------|--------|
| URLパラメータ | ❌ 長い | ✅ | ✅ | ⭐ 簡単 | ⭐⭐⭐ |
| LocalStorage | ✅ クリーン | ❌ | ✅ | ⭐⭐ やや簡単 | ⭐⭐⭐⭐ |
| SessionStorage | ✅ クリーン | ❌ | ❌ | ⭐⭐ やや簡単 | ⭐⭐ |
| メモリ内状態 | ✅ クリーン | ❌ | ❌ | ⭐ 簡単 | ⭐ |
| ハイブリッド | ✅ クリーン | ✅ | ✅ | ⭐⭐⭐ やや複雑 | ⭐⭐⭐⭐⭐ |

---

## 結論

**ハイブリッド方式（方法5）**を推奨します。既存のLocalStorage実装を活用しつつ、URLパラメータとの互換性も保てます。
