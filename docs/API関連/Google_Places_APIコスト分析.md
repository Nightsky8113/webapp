# Google Places API コスト分析

## 📊 現在のアプリの使用パターン分析

### 検索が発生するシナリオ

1. **「位置情報から探す」をクリック**
   - ユーザーの現在地から近くの店舗を表示
   - 現在はデータベースの店舗のみ表示
   - **実装後**: Places APIで近くのスーパーを検索

2. **「商品から探す」→ ジャンル選択**
   - ジャンル別の店舗を表示
   - 現在はデータベースの店舗のみ表示
   - **実装後**: この場合はPlaces APIは使用しない想定

3. **商品検索**
   - 検索キーワードで商品を検索
   - 現在はデータベースの商品のみ検索
   - **実装後**: この場合はPlaces APIは使用しない想定

**実装内容**:

2. 「近くのスーパーを検索」ボタンを追加

4. 検索結果を30分間キャッシュ

## 📊 コスト削減対策

### 1. キャッシュ機能（必須）

```javascript
// 30分間キャッシュ
const CACHE_DURATION = 30 * 60 * 1000;

// 位置情報をキーにしてキャッシュ
// 同じ位置情報（±100m以内）の場合はキャッシュを使用
```

**効果**: リクエスト数を約80-90%削減

---

### 2. リクエスト制限

```javascript
// 1ユーザーあたり1日3回まで
const MAX_REQUESTS_PER_USER = 3;
```

**効果**: 異常な使用を防止

---

### 3. 位置情報の精度を下げる

```javascript
// 位置情報を丸める（例: ±100m以内は同じとみなす）
function roundLocation(lat, lng) {
    return {
        lat: Math.round(lat * 100) / 100,
        lng: Math.round(lng * 100) / 100
    };
}
```

**効果**: キャッシュの効率が向上

## 🎯 結論

### 現在の検索条件での無料利用可能範囲（2025年最新）

**推奨実装パターン（オプション機能 + キャッシュ）の場合**:

- ✅ **約150-160ユーザー/日まで無料枠内で運用可能**
- ✅ **1か月あたり約5,000リクエストまで無料**
- ⚠️ **それ以上は課金が発生**（1,000リクエストあたり$32）

**詳細**:
- 無料枠: 5,000リクエスト/月
- 1ユーザー/日あたりの想定検索回数: 0.5-1回
- 最大ユーザー数: 5,000 ÷ 30日 ÷ 1回 = 約166ユーザー/日（無料枠内）

### 実装推奨事項

1. **オプション機能として実装** - ユーザーが選択できるようにする
2. **キャッシュ機能を実装** - 30分間キャッシュ
3. **リクエスト制限を実装** - 異常な使用を防止
4. **モニタリングを実装** - 使用量を追跡

これにより、無料枠内で安全に運用できます。
