# Google Gemini API 使用量確認方法

## 📊 使用量を確認できるサイト

Google Gemini APIの使用量を確認する方法は、APIキーの取得方法によって異なります。

---

## 🔍 方法1: Google AI Studio（推奨・簡単）

Google AI StudioからAPIキーを取得した場合：

### 確認手順

1. **Google AI Studioにアクセス**
   - URL: https://aistudio.google.com/
   - Googleアカウントでログイン

2. **使用量を確認**
   - 左側のメニューから「Usage」または「使用量」を選択
   - 現在の使用量が表示されます

3. **無料枠の詳細**
   - 1分あたり15リクエスト
   - 1日あたり1,500リクエスト
   - 個人開発・テスト目的でほぼ無制限

### ⏰ 無料枠のリセットタイミング

- **米国太平洋時間の午前0時**（日本時間の午後5時または午後4時、夏時間による）
- この時間を過ぎると、使用量がリセットされます

---

## 🔍 方法2: Google Cloud Console

Google Cloudプロジェクトとして管理している場合：

### 確認手順

1. **Google Cloud Consoleにアクセス**
   - URL: https://console.cloud.google.com/
   - Googleアカウントでログイン

2. **プロジェクトを選択**
   - 画面上部のプロジェクト名をクリック
   - Gemini APIを使用しているプロジェクトを選択

3. **APIとサービスのダッシュボードを開く**
   - 左側のメニューから「APIとサービス」>「ダッシュボード」を選択

4. **Generative Language APIを選択**
   - 有効なAPIの一覧から「Generative Language API」をクリック

5. **割り当てとシステム上限を確認**
   - APIの詳細ページで「割り当てとシステム上限」タブを開く
   - モデルごとの使用量と上限を確認

### 請求情報の確認

1. **請求セクションを開く**
   - 左側のメニューから「請求」を選択

2. **使用量の詳細を確認**
   - APIの使用量や課金状況を詳細に確認できます

3. **予算アラートを設定（推奨）**
   - 使用量が特定の閾値を超えた際に通知を受け取れます

## 🚨 429エラー（使用量制限）が発生した場合

### エラーの意味

```
Resource exhausted. Please try again later.
```

このエラーは、以下のいずれかの制限に達したことを示します：

1. **レート制限（1分あたり15リクエスト）**
   - 短時間に大量のリクエストを送信した
   - 解決策: 少し待ってから再試行

2. **日次制限（1日あたり1,500リクエスト）**
   - 1日の使用量上限に達した
   - 解決策: 翌日のリセット（米国太平洋時間の午前0時）を待つ

### 対処方法

1. **しばらく待つ**
   - レート制限の場合: 1-2分待ってから再試行
   - 日次制限の場合: 翌日のリセット時刻まで待つ

2. **リクエスト頻度を減らす**
   - 複数のOCR処理を連続で実行しない
   - 処理の間に待機時間を設ける

3. **使用量を確認する**
   - 上記の方法で使用量を確認
   - どの制限に達しているかを特定

4. **エラーハンドリングの改善（開発者向け）**
   - リトライロジックを実装
   - エラー時の待機時間を追加

## 📝 現在の実装での対応

### エラーメッセージ

現在の実装では、429エラーが発生すると以下のメッセージが表示されます：

```
API使用量制限に達しました。しばらく待ってから再試行してください。
```

### 改善案

将来的に以下の改善が可能です：

1. **自動リトライ機能**
   - エラー発生時に自動的にリトライ
   - 指数バックオフで待機時間を増やす

2. **使用量の事前確認**
   - API使用前に使用量を確認
   - 制限に近づいたら警告を表示

## 💡 ヒント

### 無料枠を有効活用する方法

1. **リクエストを最適化**
   - 不要なリクエストを減らす
   - バッチ処理を検討

2. **キャッシュを活用**
   - 同じ内容の処理結果をキャッシュ
   - 再処理を避ける

3. **処理の優先順位付け**
   - 重要な処理から実行
   - 不要な処理を後回しにする
