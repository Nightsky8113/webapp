## 🎯 このアプリはどう動いているの？

まず、このアプリケーションがどのように動いているかを、簡単に説明します。

### ブラウザでWebサイトを見る流れ

1. **ユーザーがブラウザでURLを開く**
   - 例: `http://localhost:3000` や `https://your-app.vercel.app`

2. **最初のページが表示される**
   - `index.html`というファイルが読み込まれます
   - この中には基本的な構造しかありません

3. **JavaScriptが動き始める**
   - `main.js`というファイルが読み込まれ、アプリが起動します

4. **ユーザーが何かをクリックすると**
   - JavaScriptがその操作を検知します
   - 必要に応じて新しいページを表示したり、データを取得したりします

### このアプリの特徴

- **ページを移動しても、実際には同じページのまま**
  - 通常のWebサイトは、ページを移動すると別のHTMLファイルを読み込みます
  - このアプリは、1つのHTMLファイルしかなく、JavaScriptで画面の内容を入れ替えます
  - これを「SPA（Single Page Application）」と呼びます

- **URLの「#（ハッシュ）」を使ってページを区別**
  - 例: `#/home`（ホームページ）、`#/store/1`（店舗1の詳細ページ）
  - ブラウザの戻る/進むボタンも使えます

## 📁 フォルダとファイルの役割

プロジェクトの中にはたくさんのファイルがあります。まずは、どこに何があるかを覚えましょう。

```
src/  ← ソースコード（実際に書いたプログラム）が入っているフォルダ
├── main.js  ← アプリを起動する最初のファイル
├── router.js  ← ページの移動を管理するファイル
│
├── pages/  ← 各ページのプログラム
│   ├── HomePage.js  ← ホームページを表示するプログラム
│   ├── StoreDetailPage.js  ← 店舗の詳しい情報を表示するプログラム
│   └── ...  ← 他にもページのプログラムが入っています
│
├── components/  ← 小さな部品（カードなど）のプログラム
│   ├── StoreCard.js  ← 店舗のカードを表示するプログラム
│   └── GenreCard.js  ← ジャンルのカードを表示するプログラム
│
├── services/  ← データベースや外部サービスとやり取りするプログラム
│   ├── dataService.js  ← データベースからデータを取ってくるプログラム
│   └── storageService.js  ← 画像をアップロードするプログラム
│
├── utils/  ← 便利な機能をまとめたプログラム
│   ├── location.js  ← 位置情報を取得するプログラム
│   ├── map.js  ← 地図を表示するプログラム
│   └── ...  ← 他にも便利なプログラムが入っています
│
├── templates/  ← HTMLのテンプレート（ひな形）
│   ├── pages/  ← 各ページのHTMLテンプレート
│   └── components/  ← カードなどのHTMLテンプレート
│
└── styles/  ← CSSファイル（デザインの定義）
    ├── pages.css  ← ページのデザイン
    └── components.css  ← カードなどのデザイン
```

## 🔍 主要なファイルの詳しい説明

### 1. `main.js` - アプリのスタート地点

**役割**: アプリを起動する最初のファイル。ここからすべてが始まります。

**何をしているか**:
1. ブラウザがこのファイルを読み込む
2. 「よし、アプリを動かそう！」と判断
3. `router.js`を呼び出して、ページの移動機能を準備
4. エラーが起きたときに備えて、エラーをキャッチする機能も準備

**なぜ必要なのか**:
- アプリを動かすには、最初に何かを「起動」する必要があります
- `main.js`は、アプリ全体の「スイッチ」のような役割です

**簡単な例え**:
- 家の電気をつけるには、最初にブレーカーを入れる必要があります
- `main.js`は、その「ブレーカー」のようなものです

### 2. `router.js` - ページ移動の司令塔

**役割**: 「今、どのページを表示すればいいか」を判断して、適切なページを表示します。

**何をしているか**:
1. URLを見る（例: `#/home`、`#/store/1`）
2. 「これはホームページだな」「これは店舗1の詳細ページだな」と判断
3. 対応するページのプログラムを呼び出す
4. ページが変わったら、また判断して新しいページを表示

**なぜ必要なのか**:
- アプリには複数のページ（ホーム、店舗一覧、店舗詳細など）があります
- どのページを表示するかは、URLを見て判断する必要があります
- `router.js`は、その「判断」をしてくれる便利なプログラムです

**簡単な例え**:
- 駅の改札口に立っている駅員さんのようなものです
- 「どこに行きたいですか？」と聞いて、適切なホームに案内してくれます

### 3. `pages/HomePage.js` - ホームページを作るプログラム

**役割**: ホームページに表示する内容を作ります。

**何をしているか**:
1. データベースから「今日更新されたチラシ」の情報を取得
2. そのチラシを表示するためのHTMLを作る
3. 「商品から探す」「位置情報から探す」というボタンも表示
4. 完成したHTMLを返す

**簡単な例え**:
- 料理のレシピ本のようなものです
- 「1. 材料を準備する」「2. 切る」「3. 煮る」という手順が書いてあります
- このプログラムも、「1. データを取ってくる」「2. HTMLを作る」「3. 返す」という手順になっています

**このファイルにある2つの関数**:

```javascript
// 1つ目: ページの内容を作る関数
export async function HomePage(userLocation) {
    // データを取ってきて、HTMLを作って、返す
}

// 2つ目: ボタンをクリックしたときの動作を設定する関数
export function attachHomePageEvents() {
    // 「商品から探す」ボタンをクリックしたら、ジャンルページに移動
    // 「位置情報から探す」ボタンをクリックしたら、店舗一覧ページに移動
}
```

### 4. `services/dataService.js` - データベースとのやり取り

**役割**: データベースから情報を取ってくる、データベースに情報を保存する、という作業を担当します。

**何をしているか**:
1. 「店舗のリストをください」というリクエストが来る
2. データベースに「店舗のリストをください」と聞く
3. データベースからリストをもらう
4. 一度取ったデータは5分間覚えておく（キャッシュ）
5. リストを返す

**なぜキャッシュが必要なのか**:
- データベースに毎回聞くと時間がかかります
- 5分以内であれば、データは変わっていない可能性が高いです
- だから、一度取ったデータは5分間覚えておいて、すぐに返すようにしています

**簡単な例え**:
- 本屋さんに「この本ありますか？」と毎回電話するのは大変です
- でも、5分前に聞いた情報なら覚えているので、すぐに答えられます
- `dataService.js`は、そんな「記憶力のいい店員さん」のようなものです

### 5. `components/StoreCard.js` - 店舗カードを作る小さなプログラム

**役割**: 店舗の情報を表示する「カード」という小さな部品を作ります。

**何をしているか**:
1. 店舗の情報（名前、住所、画像など）を受け取る
2. その情報を使って、きれいなカードのHTMLを作る
3. 完成したカードのHTMLを返す

**なぜ小さな部品に分けるのか**:
- 店舗のカードは、ホームページでも店舗一覧ページでも使われます
- 同じプログラムを2回書くのは無駄です
- だから、1つのプログラム（コンポーネント）を作って、どこでも使えるようにしています

**簡単な例え**:
- レゴブロックのようなものです
- 1つのブロック（コンポーネント）を作っておけば、いろんな場所で組み合わせて使えます

### 6. `utils/template.js` - HTMLテンプレートを処理するプログラム

**役割**: HTMLの「ひな形」にデータを当てはめて、完成したHTMLを作ります。

**どう動くか（具体例）**:

HTMLテンプレート（`templates/components/store-card.html`）:
```html
<h3>${storeName}</h3>
<p>${distanceText} km</p>
```

JavaScriptでデータを渡す:
```javascript
const data = {
    storeName: "イオン",
    distanceText: "1.5"
}
```

`template.js`が処理して、完成したHTMLを作る:
```html
<h3>イオン</h3>
<p>1.5 km</p>
```

**なぜテンプレートを使うのか**:
- HTMLとJavaScriptを分けることで、デザインを変えたいときにHTMLだけを変更できます
- プログラムのコードを見なくても、HTMLファイルを見れば、どんな画面になるか分かります

**簡単な例え**:
- 年賀状の印刷のようなものです
- ひな形（テンプレート）があり、そこに名前や住所を当てはめるだけです
- 何百枚印刷しても、ひな形は1つで済みます

### 7. `utils/location.js` - 位置情報を取得するプログラム

**役割**: ユーザーが今いる場所（緯度・経度）を取得します。

**何をしているか**:
1. ブラウザに「今いる場所を教えて」と聞く
2. ブラウザが「ここです」と答える（ユーザーの許可が必要）
3. その位置情報を覚えておく（LocalStorageに保存）
4. 次回は、ブラウザに聞かなくても、覚えている位置情報を返す

**なぜ位置情報が必要なのか**:
- 「近くの店舗」を表示するには、ユーザーが今どこにいるかを知る必要があります
- 位置情報があれば、「この店までは1.5km」のように距離を計算できます

**簡単な例え**:
- GPSナビゲーションのようなものです
- 「今、どこにいますか？」と聞いて、「そこから目的地まで○kmです」と教えてくれます

## 📦 データの流れ

### データベースからデータを取ってくる流れ

```
1. ページのプログラムが「店舗のデータが欲しい」と dataService.js に頼む
   ↓
2. dataService.js が「キャッシュ（5分以内に取ったデータ）があるか」を確認
   ↓
3. キャッシュがあれば → そのデータをすぐに返す（早い！）
   ↓
   キャッシュがなければ → データベースに聞く
   ↓
4. supabase.js を使って、データベースに「店舗のリストをください」と聞く
   ↓
5. データベースがリストを返す
   ↓
6. dataService.js がリストをキャッシュに保存して、ページに返す
   ↓
7. ページのプログラムが、そのデータを使ってHTMLを作る
```

### 画像をアップロードする流れ

```
1. 管理者が AdminUploadPage で画像ファイルを選択
   ↓
2. 「アップロード」ボタンをクリック
   ↓
3. storageService.js がファイルをチェック（サイズ、形式）
   ↓
4. 問題なければ、Supabase Storage にアップロード
   ↓
5. アップロードが成功したら、画像のURL（アドレス）を取得
   ↓
6. dataService.js を使って、そのURLをデータベースに保存
   ↓
7. 「アップロード成功！」と表示
```

## 💡 よくある「なぜ？」への答え

### Q1: なぜ、HTMLとJavaScriptとCSSを分けているの？

**答え**: それぞれの役割が違うからです。

- **HTML**: 「ここにタイトルを表示する」「ここにボタンを配置する」という構造を決める
- **CSS**: 「ボタンの色は青」「文字の大きさは18px」という見た目を決める
- **JavaScript**: 「ボタンをクリックしたら、この処理をする」という動きを決める

分けることで、デザインを変えたいときはCSSだけを変えればよく、機能を変えたいときはJavaScriptだけを変えればよくなります。

### Q2: なぜ「async」や「await」を使っているの？

**答え**: データベースやファイルの読み込みには時間がかかるからです。

- 普通の処理は、順番に実行されます（1つ終わってから次）
- でも、データベースに聞くのは時間がかかるので、待っている間に他のことをできた方が効率的です
- `async`と`await`を使うと、「この処理が終わるまで待って、終わったら次に進む」という動作になります

**簡単な例え**:
- 料理をするとき、「お湯を沸かす」のを待っている間に「野菜を切る」ことができます
- でも、「お湯が沸いたらパスタを入れたい」場合は、お湯が沸くまで待つ必要があります
- `await`は、「お湯が沸くまで待つ」ようなものです

### Q3: なぜ「export」を使っているの？

**答え**: 他のファイルで使えるようにするためです。

- `export`を付けると、その関数や変数を他のファイルから使えます
- 例えば、`StoreCard.js`で`export function StoreCard()`と書くと、`HomePage.js`からも`StoreCard()`を使えます

**簡単な例え**:
- 自分の家の道具を、隣の家の人にも使ってもらいたい場合、道具を「外に出しておく（export）」必要があります
- 外に出しておかないと、隣の人はその道具を使えません

### Q4: なぜ「テンプレート」を使っているの？

**答え**: HTMLを何度も書かなくて済むからです。

- 同じようなHTMLを何度も書くのは無駄です
- ひな形（テンプレート）を1つ作って、そこにデータを当てはめるだけで、何個でもHTMLを作れます

**具体例**:
- 店舗カードが100個必要でも、テンプレートは1つだけ
- データが100個あるので、テンプレートに100回データを当てはめるだけで、100個のカードができます

## 🛠️ 開発するときのポイント

### 1. ファイルを追加・変更するときの順番

新しいページを追加する場合：

1. **HTMLテンプレートを作る**
   - `src/templates/pages/新しいページ.html` を作る
   - どんな画面にしたいか、HTMLで書く

2. **ページのプログラムを書く**
   - `src/pages/新しいページ.js` を作る
   - データを取ってきて、HTMLテンプレートに当てはめる処理を書く

3. **ルーターに登録する**
   - `src/router.js` を開く
   - `routes` というオブジェクトに、新しいルートを追加する

4. **スタイルを追加する（必要に応じて）**
   - `src/styles/pages.css` に、新しいページのスタイルを追加する

### 2. デバッグ（バグを直す）のコツ

- **ブラウザの開発者ツールを使う**
  - F12キーを押すと、開発者ツールが開きます
  - 「Console（コンソール）」タブを見ると、エラーメッセージが表示されます

- **console.log() で確認する**
  - プログラムの中に `console.log('ここまできた')` と書くと、ブラウザのコンソールに「ここまできた」と表示されます
  - どこまで処理が進んでいるかが分かります

- **小さく分けて確認する**
  - 一度にたくさんのことを変えると、どこが悪いか分からなくなります
  - 少しずつ変えて、動くか確認しながら進めましょう

### 3. 他の人のコードを理解するとき

1. **まず、何をしているファイルか確認する**
   - ファイル名を見ると、だいたい何をしているか分かります
   - 例: `HomePage.js` は、ホームページに関する処理をしています

2. **関数の名前を見る**
   - 関数名を見ると、その関数が何をするか分かります
   - 例: `getStores()` は、店舗を取得する関数です

3. **コメントを読む**
   - 各関数の上に書いてあるコメントを読むと、その関数が何をしているか分かります

4. **上から順番に読む**
   - プログラムは、上から下に実行されます
   - 上から順番に読むと、処理の流れが分かります

## 🎓 学習のヒント

### 初心者におすすめの学習順序

1. **まず、1つのページを理解する**
   - `HomePage.js` を開いて、何をしているか1行ずつ読んでみましょう
   - 分からない部分は、コメントを見たり、調べたりしましょう

2. **次に、データの流れを追う**
   - ページがデータベースからデータを取ってくる流れを追ってみましょう
   - `dataService.js` を見て、どうやってデータを取っているか確認しましょう

3. **最後に、全体の流れを理解する**
   - ユーザーがボタンをクリックしてから、ページが変わるまでの流れを追ってみましょう

### 分からなくなったときは

- **エラーメッセージを読む**: エラーが出たら、そのメッセージを読んでみましょう
- **小さくテストする**: 大きなプログラムではなく、小さなプログラムを作って、動かしてみましょう
- **調べる**: 分からない言葉や概念は、インターネットで調べましょう
- **コメントを増やす**: 自分が書いたコードには、コメントをたくさん書いておきましょう

## ❓ よくある質問

### Q: 「モジュール」「コンポーネント」「サービス」って何？

**A**: 役割ごとに分けたプログラムのグループのことです。

- **モジュール**: 1つのファイルのことを指すことが多いです
- **コンポーネント**: 画面に表示する小さな部品（カード、ボタンなど）のこと
- **サービス**: データベースや外部サービスとやり取りするプログラムのこと

### Q: 「非同期」って何？

**A**: 時間がかかる処理を、待たずに他の処理を続けられる仕組みです。

- 普通の処理は「1つ終わってから次」という順番です
- 非同期処理は「この処理は時間がかかるから、終わるまで待ってる間に他のことをやろう」という感じです

### Q: 「キャッシュ」って何？

**A**: 一度取ったデータを覚えておいて、すぐに返せるようにすることです。

- データベースに聞くのは時間がかかります
- でも、5分前に聞いたデータなら、まだ有効な可能性が高いです
- だから、一度取ったデータは5分間覚えておいて、すぐに返します
